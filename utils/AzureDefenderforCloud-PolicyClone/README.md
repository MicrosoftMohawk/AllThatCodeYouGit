# Regulatory Compliance Custom Initiative - Deployment Guide

## Overview

Azure's built-in regulatory compliance initiatives (NIST 800-53 R5, CIS, HIPAA, PCI DSS, FedRAMP, etc.) **cannot be exported through the Azure Portal**. This tooling uses Az PowerShell to:

1. **Export** any built-in compliance initiative
2. **Transform** the export from built-in → custom format (PascalCase → camelCase, strip built-in-only fields, set `policyType: Custom`)
3. **Create or update** the custom initiative definition at a subscription or management group
4. **Optionally assign** the initiative so it appears in Microsoft Defender for Cloud

The custom version allows you to:
- Modify policy definitions (add/remove/adjust)
- Apply to management groups or subscriptions
- Create policy exemptions for specific resources
- Maintain version control over your compliance framework

## Prerequisites

### Required Azure Modules
```powershell
# Install or update Azure PowerShell modules
Install-Module Az.Resources -Scope CurrentUser -Force
Install-Module Az.PolicyInsights -Scope CurrentUser -Force
```

### Required Permissions
- **Management Group Level**: Management Group Contributor or Policy Contributor
- **Subscription Level**: Owner or Policy Contributor
- **For Remediation**: Contributor role (or specific resource permissions)

## Quick Start

### Step 1: Run the Deployment Script

```powershell
# Interactive mode — prompts for everything
.\Deploy-CustomNIST-Initiative.ps1

# Or with parameters for semi-automated use
.\Deploy-CustomNIST-Initiative.ps1 -SearchFilter "NIST" -InitiativeName "NIST-R5-Custom"
```

The script walks you through:
1. Authenticate to Azure (or reuse existing session)
2. Select a subscription
3. Choose deployment scope (Management Group or Subscription)
4. Search and select a built-in compliance initiative (NIST, CIS, HIPAA, etc.)
5. Export and **transform** the built-in initiative to custom format
6. Create (or update) the custom initiative definition
7. Optionally assign the initiative

### Available Parameters

| Parameter | Description |
|-----------|-------------|
| `-SubscriptionId` | Azure Subscription ID (skips interactive selection) |
| `-ManagementGroupId` | Target Management Group name/ID |
| `-InitiativeName` | Custom initiative name (max 64 chars, alphanumeric/hyphens/underscores) |
| `-SearchFilter` | Text to filter compliance initiatives (e.g., "NIST", "CIS") |
| `-JsonOutputPath` | Directory for exported JSON files (default: script directory) |
| `-SkipAssignment` | Skip the optional assignment prompt |
| `-SkipExport` | Skip export step, use existing `custom_initiative.json` |
| `-WhatIf` | Preview what would happen without making changes |
| `-Verbose` | Show detailed output |

### Step 2: Customize (Optional)

After the first run, your `custom_initiative.json` contains the transformed initiative. You can:

1. Open `custom_initiative.json`
2. Add/remove policies from the `policyDefinitions` array
3. Adjust parameters as needed
4. Save and re-run: `.\Deploy-CustomNIST-Initiative.ps1 -SkipExport`

The JSON uses ARM-compatible **camelCase** format:
```json
{
  "policyType": "Custom",
  "displayName": "NIST SP 800-53 Rev. 5",
  "description": "...",
  "parameters": {},
  "policyDefinitions": [
    {
      "policyDefinitionId": "/providers/Microsoft.Authorization/policyDefinitions/...",
      "policyDefinitionReferenceId": "...",
      "groupNames": ["NIST_SP_800-53_R5_CM-6"],
      "parameters": {}
    }
  ],
  "policyDefinitionGroups": [
    {
      "name": "NIST_SP_800-53_R5_AC-1",
      "additionalMetadataId": "..."
    }
  ]
}
```

### Step 3: Assign the Initiative

If you skipped assignment during the script, assign manually:

#### Option A: Azure Portal
1. Navigate to **Azure Portal > Policy > Definitions**
2. Set **Type** filter to **Custom**
3. Find your initiative by name
4. Click the initiative, then click **Assign**
5. Select scope, configure parameters, enable Managed Identity
6. Review and create

#### Option B: PowerShell
```powershell
$initName = "NIST-SP-800-53-Rev--5-Custom"  # your initiative name
$scope = "/subscriptions/YOUR-SUB-ID"
# $scope = "/providers/Microsoft.Management/managementGroups/YOUR-MG-ID"

$init = Get-AzPolicySetDefinition -Name $initName -SubscriptionId "YOUR-SUB-ID"
New-AzPolicyAssignment `
    -Name "NIST-R5-Assignment" `
    -DisplayName "NIST 800-53 R5 Custom" `
    -Scope $scope `
    -PolicySetDefinition $init `
    -Location "eastus" `
    -IdentityType "SystemAssigned"

# Grant RBAC to the managed identity
$assignment = Get-AzPolicyAssignment -Name "NIST-R5-Assignment"
New-AzRoleAssignment `
    -ObjectId $assignment.Identity.PrincipalId `
    -RoleDefinitionName "Contributor" `
    -Scope $scope
```

**Important Notes:**
- Assignment name must be **24 characters or less**
- Enable **System Assigned Managed Identity** for `deployIfNotExists` / `modify` effects
- Grant the managed identity appropriate RBAC roles for remediation
- Compliance evaluation begins **10-30 minutes** after assignment

### Step 4: Manage Policy Exemptions

```powershell
# Load the helper functions
. .\Manage-PolicyExemptions.ps1

# Example: Exempt a development resource group
New-PolicyExemptionForResourceGroup `
    -ResourceGroupName "rg-dev" `
    -ExemptionName "dev-env-exemption" `
    -ExemptionCategory "Waiver" `
    -ExpirationMonths 6 `
    -Reason "Development environment - testing in progress"

# Generate exemption report
$report = Get-ExemptionReport
$report | Format-Table -AutoSize
```

## How the Transformation Works

The script solves a critical problem: Azure's `Get-AzPolicySetDefinition` exports built-in initiatives in a **PascalCase PowerShell object format** that differs from the **camelCase ARM REST API format** required for custom initiative creation.

### What Gets Transformed

| Built-in Export (PascalCase) | Custom Output (camelCase) |
|------------------------------|--------------------------|
| `PolicyDefinition` | `policyDefinitions` |
| `PolicyDefinitionId` | `policyDefinitionId` |
| `GroupName` | `groupNames` |
| `Id` (reference ID) | `policyDefinitionReferenceId` |
| `Parameter` | `parameters` |
| `PolicyDefinitionGroup` | `policyDefinitionGroups` |
| `PolicyType: "BuiltIn"` | `policyType: "Custom"` |

### What Gets Stripped

Built-in-only fields are removed from the export:
- `Id` (the built-in resource ID)
- `Name` (the built-in GUID)
- `PolicyType: "BuiltIn"`
- `SystemData*` fields
- `Type`, `Version`, `Versions`
- `DefinitionVersion` on each policy definition

## Common Scenarios

### Scenario 1: Export NIST 800-53 R5 and Deploy

```powershell
.\Deploy-CustomNIST-Initiative.ps1 -SearchFilter "NIST"
```

### Scenario 2: Export CIS Benchmark

```powershell
.\Deploy-CustomNIST-Initiative.ps1 -SearchFilter "CIS"
```

### Scenario 3: Re-deploy After Editing JSON

```powershell
# Edit custom_initiative.json, then:
.\Deploy-CustomNIST-Initiative.ps1 -SkipExport -InitiativeName "My-Custom-NIST"
```

### Scenario 4: Idempotent Update (Initiative Already Exists)

The script detects existing initiatives and prompts:
- **[U] Update** — uses `Set-AzPolicySetDefinition`
- **[S] Skip** — keeps existing, proceeds to assignment
- **[A] Abort** — exits

### Scenario 5: Non-Interactive / CI Pipeline

```powershell
.\Deploy-CustomNIST-Initiative.ps1 `
    -SubscriptionId "00000000-0000-0000-0000-000000000000" `
    -InitiativeName "NIST-R5-Custom" `
    -SearchFilter "NIST SP 800-53 Rev. 5" `
    -SkipAssignment `
    -Verbose
```

### Scenario 6: Find Policy Reference IDs

```powershell
$json = Get-Content .\custom_initiative.json -Raw | ConvertFrom-Json
$json.policyDefinitions |
    Select-Object policyDefinitionReferenceId, policyDefinitionId |
    Format-Table
```

## Monitoring and Compliance

### View Compliance Status

```powershell
# Compliance summary
Get-AzPolicyStateSummary -SubscriptionId "YOUR-SUB-ID"
# Get-AzPolicyStateSummary -ManagementGroupName "YOUR-MG-ID"

# Detailed compliance state
$compliance = Get-AzPolicyState -PolicyAssignmentName "YOUR-ASSIGNMENT-NAME"
$compliance | Select-Object ResourceId, ComplianceState, PolicyDefinitionName | Format-Table
```

### Trigger Compliance Scan

```powershell
Start-AzPolicyComplianceScan -AsJob
```

### Export Compliance Report

```powershell
$assignment = Get-AzPolicyAssignment -Name "YOUR-ASSIGNMENT-NAME"
$compliance = Get-AzPolicyState -PolicyAssignmentId $assignment.ResourceId

$compliance | Select-Object `
    ResourceId, ComplianceState, PolicyDefinitionName,
    @{Name="ResourceGroup"; Expression={$_.ResourceGroup}} |
Export-Csv "Compliance_Report_$(Get-Date -Format 'yyyyMMdd').csv" -NoTypeInformation
```

## Remediation

```powershell
$assignment = Get-AzPolicyAssignment -Name "YOUR-ASSIGNMENT-NAME"
$scope = "/subscriptions/YOUR-SUB-ID"

# Remediate all non-compliant resources
Start-AzPolicyRemediation `
    -Name "remediate-all-$(Get-Date -Format 'yyyyMMdd')" `
    -PolicyAssignmentId $assignment.ResourceId `
    -Scope $scope

# Remediate specific policy
Start-AzPolicyRemediation `
    -Name "remediate-sql-audit" `
    -PolicyAssignmentId $assignment.ResourceId `
    -PolicyDefinitionReferenceId "EnableAuditingOnSQLServers" `
    -Scope $scope

# Monitor progress
Get-AzPolicyRemediation -Scope $scope
```

## Best Practices

1. **Version Control** — Keep `custom_initiative.json` in git. Use branches for testing.
2. **Exemption Management** — Always set expiration dates. Document justification. Review quarterly.
3. **Testing** — Test in a dev/test subscription first. Use `-WhatIf`.
4. **RBAC** — Grant managed identity appropriate roles immediately after assignment.
5. **Monitoring** — Set up Azure Monitor alerts for compliance changes. Schedule regular reports.
6. **Transcript Logs** — The script creates timestamped log files in the output directory.

## Troubleshooting

### Initiative Creation Fails
- Verify JSON is valid: `Get-Content .\custom_initiative.json | ConvertFrom-Json`
- Check permissions: Policy Contributor or Owner at target scope
- If initiative exists, script will prompt to Update, Skip, or Abort
- For large initiatives, check Azure size limits

### Compliance Data Not Showing
- Wait 10-30 minutes for initial evaluation
- Trigger: `Start-AzPolicyComplianceScan`
- Verify assignment was successful

### Remediation Not Working
- Ensure managed identity has RBAC roles
- Verify the policy supports remediation (`deployIfNotExists` / `modify` effect)
- Check: `Get-AzPolicyRemediation`

### Parameters Empty After Export
- Some built-in initiatives export parameters as `{}` via PowerShell
- Edit `custom_initiative.json` to add parameters manually if needed
- Individual policies will use their default effect values
